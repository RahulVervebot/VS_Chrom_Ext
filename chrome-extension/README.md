# AI Project Bridge (Chrome extension)

The **AI interaction** half of the system. It receives project context from VS Code, drives your own ChatGPT / Claude / Gemini tab, validates the answers, and returns structured knowledge. It is not the source of truth and never touches project files. Step-by-step usage is in the [root README](../README.md).

## Installation
```bash
npm install && npm run build
```
Chrome → `chrome://extensions` → **Developer mode** → **Load unpacked** → select this folder (the one containing `manifest.json`). Click the toolbar icon to open the side panel.

## Development
| Script | Purpose |
|---|---|
| `npm run build` / `watch` | esbuild → `dist/background.js`, `content-*.js`, `panel.js/css`; icons generated by `scripts/icons.cjs` |
| `npm test` | 35 tests: response parser, schema, sanitizer, merger, secrets, batching, prompts, adapters on fixture DOMs (jsdom), orchestrator ↔ real VS Code bridge |
| `npm run test:e2e` | real Chrome + this unpacked extension + a local HTTPS `chatgpt.com` stand-in + the real VS Code bridge |

Manifest V3 · JavaScript · React (JSX) · no TypeScript. After editing code, rebuild and click *reload* on the extension card.

## Supported AI providers
| Provider | Hosts | Adapter |
|---|---|---|
| ChatGPT | chatgpt.com, chat.openai.com | `src/ai/chatgptAdapter.js` |
| Claude | claude.ai | `src/ai/claudeAdapter.js` |
| Gemini | gemini.google.com | `src/ai/geminiAdapter.js` |
| Other | a site you allow in Settings (asks Chrome for permission) | `src/ai/genericAdapter.js` (heuristic, lower confidence) |

All website-specific selectors live in those files as ordered lists. The shared behaviour is in `aiAdapter.js`:
`detect · getCapabilities · getInputBox · enterPrompt · submitPrompt · detectResponse · readResponse · detectError · detectLimit`.
Safety rules built into `run()`: refuse on login/captcha/limit pages; require an editable, visible message box; verify the prompt actually landed (length and both ends) before pressing send; treat any answer that existed before the send as old; report `UI_CHANGED` and stop if anything required is missing. **The selectors are unverified against the live sites** (see the root README's limitations); use *Settings → Check provider*.

## VS Code pairing
1. VS Code: **AI Project: Pair Chrome** → a code like `47821-7K3M9QX2LPWA` (the port is the number in front). 2. Panel → Connection → paste the whole code → Pair. 3. Approve in VS Code. The session key is kept in `chrome.storage.local`; reconnect is automatic (`chrome.alarms` keep-alive + backoff).

## Several projects
Chrome holds one pairing at a time. Pairing with a different project **suspends** the previous project's unfinished analyses (status PAUSED, progress kept). Analyses are stored per project (`<projectId>~<analysisId>`), so two projects can both have an `analysis-001`. Messages are addressed to the project they belong to: a result finished for project A while Chrome is connected to B is queued and delivered only when A reconnects. Reconnect A and run *Resume Analysis* in VS Code to finish.

## How an analysis runs
`ANALYSIS_REQUEST` → panel shows the privacy review → you approve → for each `ANALYSIS_BATCH`:
limits applied → specialized prompt (file / workflow / database / feature / architecture / change) → secret re-check → tab → answer → JSON extracted and validated → (one correction prompt if invalid; split the batch if cut off or too large) → hashes and paths checked against the batch (`knowledge/sanitizer.js`) → **checkpoint** → `AI_RESPONSE`. After the last batch the merged `KNOWLEDGE_PACKAGE` is sent. Results produced while offline are queued and delivered after the session resumes.

See [BRIDGE-PROTOCOL.md](../BRIDGE-PROTOCOL.md). Client code: `src/bridge/`.

## Security
Loopback only; pairing code + user approval; no API keys or passwords are requested or stored; prompts are scanned for secrets right before typing; permissions are limited to storage, side panel, scripting, alarms, downloads and the four AI hosts (other sites only via an explicit optional-permission prompt); AI output is never sent to VS Code unless it validates; Chrome cannot modify files.

## Troubleshooting
Panel → **Settings → Check provider** for interface problems. Service worker console: `chrome://extensions` → *Inspect views: service worker*. Storage: DevTools → Application → Extension storage. **Clear stored data** resets analyses/jobs/results (VS Code data is unaffected).
